RemotingProbe.exe ― PullerView 検証ツール（1対1接続版：ホスト VB_FERROTEC_SERVER なし／Python 不要／ネットワーク不要）

【仕組み】 VB_FERROTEC.exe は起動時にホストへ「接続しに行く」。本ツールがホスト側（待機側）を代行する。
   1) TCP SocketPort で VB_FERROTEC.exe の接続を待ち、SessionID を返信（これ以外は送信しない）
   2) Remoting RemotePort に clsPcObj を公開し、VB_FERROTEC.exe が毎秒書き込む値を読み取って表示・CSV 保存
   ※ VB_FERROTEC_SERVER が同じポートで動いていると競合する。どちらか一方だけ起動すること。

【準備】 このフォルダに VB_FERROTEC.exe と同じフォルダの次の3ファイルをコピー（同一ファイルを使うこと）
   VB_FERROTEC_Common.dll / Application.ini / Ment.ini
   Application.ini [Server] の HostIP がこのPC自身（127.0.0.1 または自PCのIP）で、SocketPort/RemotePort が
   VB_FERROTEC.exe が使う値であること。

【手順】
   1. RemotingProbe.exe を実行（「接続を待っています」と表示）
   2. VB_FERROTEC.exe を起動（すでに起動中なら再起動。再接続は g_ReConnectTime 秒ごとに自動で行われる）
   3. [SOCKET] TextID=00 受信 … SessionID を返信、のあと値が毎秒表示されれば成功。Ctrl+C で終了
   オプション: --seconds 60  --indices 65,92,115,116,117,118,119  --csv poc_result.csv

【出力】 画面と poc_result.csv（時刻, 取得ms, intIOBit長, 工程, PLC, 結晶長, 工程別長さ, idx65, idx92, idx115〜119）
【合格目安】 intIOBit長=2100、idx65 が VB_FERROTEC 画面の直径表示と一致、ERR なし
【失敗時】 画面の表示全体と poc_result.csv を共有してください。
【動作要件】 Windows 10 x64 / .NET Framework 4.x（標準）。管理者権限不要（ポート待受けで Windows ファイアウォールの確認が出たら、同一PC接続のみなら「キャンセル」でも可）。

【2026-10-21 更新】
 ・VB_FERROTEC.exe は同じ接続上で ReConnect_Time 秒ごとに TextID=00 を再送する。本ツールは最初の 00 だけ処理し、
   2回目以降は無視する（以前は毎回オブジェクトを作り直していたため、約 14 秒ごとに値が途切れていた）。
 ・stcMCValue（項目名・除数）は VB_FERROTEC.exe 起動後の初回接続時にしか送られない。受信時に mcmeta.csv へ保存し、
   次回以降は mcmeta.csv の除数で代用する（CSV の divsrc 列: remoting=受信値 / file=mcmeta.csv / none=除数不明→raw:生値）。
   除数を受信したいときは VB_FERROTEC.exe を再起動する。

【2026-10-21 更新2】
 ・--all    : stcMCValue 全項目（150 列）を CSV に出力する（列名は CSV 2 行目のコメントに記載）
 ・--quiet  : 画面表示を 10 秒に 1 行へ間引く
 ・読取りに 500ms 以上かかった場合、どの項目で遅延したか・GC 回数・メモリ・スレッド数を画面ログに出す
 ・process 列は VB_FERROTEC の g_strAutoLogStatus そのもの。値は
   AUTO(自動モードだが工程未開始) / STATUS_CHECK / VACUUM / LEAK_CHECK / MELT / STABILIZE / NECK / CROWN / SHOULDER / BODY / TAIL /
   ANEEL / SHUTDOWN / MANUAL / WAITMATERIALS / MAINTENANCE
   → PullerView の工程判定はこの文字列で行える（NECK〜TAIL のときだけグラフ対象）
